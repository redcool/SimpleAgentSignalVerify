# defect-loop-review

审核不是"再读一遍给意见"。审核是**把一堆散落的意见，压成少数几条规则**，让同类问题不再长出来。

## 什么时候用

- 有一份交付物，要找问题并改到能发（不是要一份感想）；
- 已经改了几轮，越改越乱，或者"改一处、坏一处"；
- 多人多轮评审，意见发散，收不了尾；
- 需要一个**能停下来的判据**，而不是"再看看"。

## 不适用

- 只想要风格建议——那是 taste，不是缺陷，本技能不处理；
- 交付物还没成型，谈不上缺陷；
- 需要专业资质的判断（医学诊断、法律意见、安全认证）——本技能只驱动流程，不替代专业判据。

## 一、先分清两个计量单位

这是最容易犯错的地方：拿"轮次"当质量尺子，等于用深度工具量宽度。

| 单位 | 方向 | 用什么工具 | 上限 |
|---|---|---|---|
| **缺陷** | 横向：一份交付物里有很多互相独立的问题 | 五步追问（第三节） | 每个缺陷五层 |
| **收敛** | 整体：改到什么时候可以停 | 净流入（第五节） | 不设轮次 |

轮次多不说明认真，只说明规则没生效。

## 二、三段式流程

### 第一段：广度（一次性全文）

审核员全文读一遍，**只交一张缺陷总表**，按类型聚类，不逐条给改法。

要求：

- 每条给位置与原句/原帧/原时间码；
- 每类给计数，例如"年份漂移 6 处""表格与正文不同步 4 处"；
- 分级只按一件事：**用户会不会踩坑。**

主笔这一段的动作是**分类，不是修**。

### 第二段：深度（逐类追问，出规则）

对每一类缺陷做五步追问（第三节），得到规则。产出形如：

- 表格必须从正文校验，不手写；
- 改年份要同时查小标题、表格、资料条目、收尾复述句；
- 删一段要查孤儿引用与悬空指代。

然后**批量修同类**——不是逐条修。改的时候按规则扫全篇。

### 第三段：验证（只审增量）

审核员只读**改动处与回填点**，不重读全文，报三类：新增、复发、未修。

这一段成本从十分钟降到两分钟，而且同类问题不会重新长出来。

## 三、五步追问：对缺陷用，不对交付物用

### 模板

> 现象 → 为什么？→ 为什么？→ 为什么？→ 为什么？→ 为什么？

挖到第五层时，得到的通常不是"改这一处"，而是"改一条规则"。

### 真实例子

> 现象：一份稿子的对照表里，德国的"高峰"写成"二战期间的生物破坏活动"。

1. 为什么错？凭印象把一战的事写成了二战。
2. 为什么凭印象？表是手写的，正文与表之间没有映射。
3. 为什么没有映射？表在正文写之前就定稿了。
4. 为什么先定稿？把它当"导航工具"，没当"正文的摘要"。
5. 为什么允许两者不同步？流程里没有回填检查、没有校验脚本。

第五层给出的是**"表格必须从正文校验，不能凭印象"**。这条规则一立，同一份表里另外三格错（起点与高峰倒置、缺年份、丢限定词）一起被扫掉。

### 边界

- 只对 A 级和"反复出现的类型"做完整五层；B、C 级改掉即可。
- 五层挖不到根因，说明问题在**证据层**（不知道事实是什么），回查证，不要继续追问。
- 产出必须落成一句可执行的规则，写进规则清单。没落成规则的追问，等于没问。

## 四、判据卡（动手前必须先写）

没有判据的审核，会退化成"AI 聊感想"。开审前先填这张卡：

```
合格线：用户在哪一步会卡住？（越具体越好，写"第一次打开就找不到开始按钮"，不写"体验不佳"）
红线：哪些错了不能发？（事实错误、合规、安全、品牌口径）
验收门槛：什么情况算过？（A 级清零？任意三条抽样通过？）
量具：哪些能用工具量？（时间码、偏移、响度、帧率、二进制大小……量得出来的，交给工具）
人审边界：哪些交给专业判断？（医学、法律、审美）
```

判断一条意见是否"必须改"，看它有没有踩在合格线或红线上。没踩的，属于 D 级。

## 五、收敛判定：净流入

不数轮次，算这个：

> **净流入 = 本轮新发现的 A/B 级 − 本轮修复造成的 A/B 级**

| 净流入 | 含义 | 动作 |
|---|---|---|
| > 0 | 还在恶化，或修复本身在制造问题 | 先查方法，不急着改 |
| = 0 | 打平 | 可以收 |
| < 0 | 修复造成的比修掉的还多 | **立刻停**，动手方式有问题 |

四条即时停手信号：

1. A 级清零，且 B 级只剩同一类型 → 收。
2. 同一类问题第二轮复发 → 停。不是交付物的问题，是流程缺一条规则。
3. 一轮耗时超过十分钟，且没有新增证据类发现 → 停，在措辞层面打转。
4. 一轮里两条以上 A 级是本轮改动造成的 → 停，回去补规则。

## 六、六条硬规则

1. **审核者与创作者上下文隔离。** 同一个模型自己审自己，会共享盲点。
2. **审核员只分类、只计数、只指认位置。** 不许写"更好的版本"，否则审核变成第二作者。
3. **分级只按"用户会不会踩坑"**，不按"专家觉得应该"。
4. **净流入计量。** 修复造成的新问题比修掉的还多，是立刻停的信号。
5. **每轮至少产出一条规则，否则这轮不算完成。**
6. **允许说"没问题"。** 明确禁止凑数，否则审核员会为了显得有用而制造工作量。

| 产物 | 内容 | 模板 |

| 判据卡 | 合格线、红线、验收门槛、量具、人审边界 | `references/判据卡.md` |

| 规则清单 | 每条一句可执行的检查规则 | `references/规则与净流入.md` |

## 八、和测量工具配合

能变成数字的，就不要用形容词。这里可以接 signalverify 这类工具：口型偏移、音画同步、响度、帧率、时间码。

分工：

- **工具量的** → 直接进 A 级证据，附方法与参数；
- **工具量不了的** → 进人审，或进 D 级，不要伪装成 A 级。

一句话：**量具负责"是不是"，本技能负责"要不要改、改完怎么停"。**

## 九、常见失败（本技能就是为了防这五种）

| 失败 | 后果 | 对策 |
|---|---|---|
| 每轮全文重读 | 成本恒定，永远收不了尾 | 第三段只审增量 |
| 逐条修 | 同类问题换个位置复发 | 先分类、出规则、批量修 |
| 为满足审核而改 | 修 A 时挖出更硬的新错 | 改前问"还有哪些地方要跟着动" |
| 无限轮次 | 三十轮之后没人记得为什么改 | 净流入与四条停手信号 |
| 把偏好写成 A 级 | 审核变成品味之争 | 分级只按用户会不会踩坑 |
